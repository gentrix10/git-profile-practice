# Git 명령어 치트시트 & 문제 해결

## 오늘 배운 명령어 한눈에 보기

### 상태 확인 (막힐 때마다 제일 먼저!)

| 명령 | 하는 일 |
|---|---|
| `git status` | 지금 저장소가 어떤 상태인지 (⭐ 가장 자주 쓰는 명령) |
| `git diff` | 아직 커밋하지 않은 변경 내용 보기 |
| `git log --oneline` | 커밋 이력을 한 줄씩 보기 |
| `git branch` | 브랜치 목록 보기 (* = 지금 있는 곳) |

### 기록하기

| 명령 | 하는 일 |
|---|---|
| `git init` | 이 폴더를 git 저장소로 만들기 |
| `git add <파일>` | 파일을 Staging Area에 올리기 (`git add .` = 전부) |
| `git commit -m "메시지"` | Staging Area의 내용을 영구 기록 |

### 브랜치

| 명령 | 하는 일 |
|---|---|
| `git switch -c <이름>` | 브랜치를 만들고 바로 이동 |
| `git switch <이름>` | 브랜치 이동 |
| `git merge <이름>` | 그 브랜치를 지금 브랜치로 합치기 |
| `git branch -d <이름>` | 병합이 끝난 브랜치 지우기 |

### GitHub (원격 저장소)

| 명령 | 하는 일 |
|---|---|
| `git remote add origin <주소>` | GitHub 저장소를 origin이라는 별명으로 등록 |
| `git push -u origin main` | 처음 올리기 (-u는 처음 한 번만) |
| `git push` | 올리기 |
| `git pull` | 받아오기 |
| `git clone <주소>` | GitHub의 저장소를 내 컴퓨터로 통째로 복제 |

### 좋은 커밋 메시지란?

- ❌ `수정`, `asdf`, `커밋` — 나중에 봐도 뭘 했는지 모름
- ✅ `취미 목록 추가`, `충돌 해결: 좋아하는 색 결정` — 무엇을 했는지 한눈에!

## 문제가 생겼을 때 🚑

### 튜토리얼 창을 실수로 닫았어요
괜찮아요! 진행 상황은 자동 저장됩니다.
`시작하기.bat`을 다시 더블클릭하면 하던 단계부터 이어서 진행돼요.

### "Please tell me who you are" 라며 커밋이 안 돼요
이름/이메일이 설정되지 않았어요.
```bash
git config --global user.name "내이름"
git config --global user.email "내이메일"
```

### 갑자기 이상한 편집기(vim)가 열렸어요!
`-m` 없이 `git commit`만 입력하면 편집기가 열려요. 당황하지 말고:
1. `Esc` 키를 누른다
2. `:q!` 를 입력하고 Enter (저장하지 않고 나가기)
3. 다시 `git commit -m "메시지"` 로 커밋
그리고 이 사고를 막으려면: `git config --global core.editor notepad`

### "nothing to commit" 이라고 나와요
커밋할 것이 Staging Area에 없다는 뜻이에요.
- 파일을 수정하고 **저장**했나요? (편집기의 저장 버튼!)
- `git add <파일>` 을 했나요?
- `git status` 로 지금 상태를 확인해 보세요.

### git log / git diff 화면에서 못 빠져나가겠어요
`q` 키를 누르면 나와집니다.

### push가 "rejected" 라며 거부됐어요
GitHub 쪽에 내 컴퓨터에는 없는 커밋이 있다는 뜻이에요. (예: 웹에서 직접 수정했거나, 짝이 먼저 push함)
```bash
git pull    # 먼저 받아온 다음
git push    # 다시 올리기
```

### 한글 파일 이름이 "\354\236..." 처럼 깨져 보여요
```bash
git config --global core.quotepath false
```

### 다른 브랜치로 이동(switch)이 안 돼요
커밋하지 않은 변경이 있으면 이동이 막힐 수 있어요.
`git status` 로 확인하고, 변경을 커밋한 뒤 이동하세요.

### 엉뚱한 브랜치에서 커밋해 버렸어요
당황하지 않아도 돼요 — 커밋이 사라진 게 아니라 위치만 다른 거예요.
`git log --oneline` 으로 어디에 커밋됐는지 확인하고, 선생님과 함께
그 브랜치를 main에 merge하는 방법으로 해결할 수 있어요.

### 충돌 마커(<<<<<<<)를 안 지우고 커밋해 버렸어요
괜찮아요, 그냥 다시 고치면 돼요.
1. 파일을 열어 `<<<<<<<`, `=======`, `>>>>>>>` 줄을 정리하고 저장
2. `git add <파일>` → `git commit -m "충돌 마커 정리"`

### 뭐가 뭔지 모르게 완전히 꼬였어요 — 처음부터 다시 시작
전혀 부끄러운 일이 아니에요. 프로 개발자도 종종 이렇게 합니다. 😄
1. 지금 폴더를 통째로 지우거나 다른 이름으로 바꿔 두고
2. 처음 받았던 zip을 다시 풀어 새 폴더를 만든 뒤
3. Git Bash를 열고 `./tutorial.sh` 부터 다시 시작하세요.
GitHub에 이미 저장소를 만들었다면: 저장소 페이지 → Settings → 맨 아래
**Delete this repository** 로 지우고 새로 만들면 됩니다.
