# 강사용 가이드

고등학생·프로그래밍 초보자 대상 Git·GitHub 실습 수업 진행 안내입니다.

## 수업 개요

- **형태**: 단계 기반(step-by-step) TUI 튜토리얼 — 학생이 `시작하기.bat`을 더블클릭하면 상단(안내 고정)/하단(터미널) 분할 화면이 자동 실행됩니다. 전체 과정은 7개 챕터, 46개 마이크로 단계이며 각 단계마다 **실행할 명령이 정확히 하나** 정해져 있습니다. 학생이 그 명령을 입력하면 실행→결과 검증→자동으로 다음 단계로 진행되고, 다른 명령은 실행되지 않고 안내만 나옵니다(구경용 `git status/log/diff` 등은 항상 허용). 파일 수정·브라우저 작업 단계는 작업 후 Enter로 검증합니다.
- **강사의 역할**: 각 차시 도입부의 개념 시연 + 순회하며 막힌 학생 지원. 화면에 항상 "지금 할 일"이 표시되고 `hint`가 보조 설명을 주므로, 학생이 손을 들기 전에 화면의 ▶ 표시와 hint를 먼저 보도록 유도하세요.
- **사전 준비물**
  - 학생 PC: Git for Windows 설치 (수업 전 설치 권장 — 설치에 5~10분 소요)
  - 학생별 GitHub 계정 (Step 5 전까지 준비 — 학교 이메일 인증이 느릴 수 있으니 미리!)
  - 이 폴더를 zip으로 압축해 배포 (**`.git` 폴더가 없는 상태** 권장 — `git init`이 Step 1의 실습이므로)
    - GitHub 저장소에 올려 두고 `git clone`으로 배포해도 됩니다: `git init` 단계가 딸려 온 기존 기록(.git)을 감지해, 학생 확인 후 지우고 깨끗한 상태에서 다시 `git init`부터 시작하도록 강제합니다
  - (짝 실습 진행 시) 2인 1조 편성

## 권장 차시 구성 (50분 × 3차시)

### 1차시 — 로컬 Git 기초 (Step 1~3)

| 시간 | 내용 |
|---|---|
| 10분 | 도입: 버전 관리가 왜 필요한가 (과제 최종_진짜최종_v2.hwp 사례) |
| 5분 | `시작하기.bat` 더블클릭 시연 + 화면 사용법(▶ 명령 입력 / Enter / hint / edit) 시연 |
| 30분 | Step 1~3 개별 진행 (강사는 순회 지원) |
| 5분 | 정리: Working Directory → Staging Area → Repository 3단계 복습 |

**시연 포인트**: `git status`를 명령 사이마다 실행해 색과 문구가 바뀌는 것을 화면으로 보여주면 3단계 모델이 쉽게 각인됩니다.

**주의**: 튜토리얼은 커밋을 항상 `-m` 옵션으로 안내하지만, 학생이 `-m` 없이 `git commit`만 입력하면 vim이 열릴 수 있습니다. 탈출법(`Esc` → `:q!` → Enter)은 cheatsheet.md에 있으니, 발생하면 그쪽으로 안내하세요.

### 2차시 — 브랜치와 GitHub (Step 4~5)

| 시간 | 내용 |
|---|---|
| 10분 | 도입: 브랜치 = 평행 우주 비유 시연 (`git switch` 후 파일 내용이 바뀌는 것을 탐색기+메모장으로 직접 보여주기 — 가장 반응이 좋은 장면) |
| 25분 | Step 4~5 개별 진행 |
| 10분 | GitHub 첫 push 지원 (브라우저 로그인 인증에서 많이 막힘) |
| 5분 | 정리: local ↔ remote 그림 복습 |

**주의**: Step 5에서 GitHub 저장소 생성 시 "Add a README file"을 체크하면 push가 거부됩니다. 튜토리얼과 `docs/github-guide.md`에 경고가 있지만 자주 발생하니, 발생 시 `git pull origin main --allow-unrelated-histories` 또는 저장소 삭제 후 재생성으로 해결하세요.

### 3차시 — 협업 흐름 (Step 6~7 + 심화)

| 시간 | 내용 |
|---|---|
| 5분 | 도입: PR = "합쳐 주세요" 요청, 실제 오픈소스 PR 화면 구경 |
| 20분 | Step 6~7 개별 진행 |
| 15분 | 심화(짝 실습): `docs/github-guide.md` ④ — 서로 Collaborator 초대, 상대 저장소에 PR, 같은 줄 동시 수정으로 자연 충돌 경험 |
| 10분 | 정리: 전체 흐름 복습 + 완주 확인 |

## 강사 전용 숨김 명령: `skip`

학생 화면(하단 안내 바, help)에는 표시되지 않는 명령입니다. `명령>` 칸에 `skip`을
입력하면 확인 질문 후 **현재 마이크로 단계 하나**를 검증 없이 건너뜁니다.
챕터 하나를 통째로 건너뛰려면 반복해서 입력하세요 (예: GitHub 챕터 5 = 3단계, 챕터 6 = 8단계).

- **용도**: 수업 시간 부족, GitHub 계정 문제(이메일 인증 지연 등)로 막힌 학생 구제,
  강사 시연 중 특정 단계로 빠르게 이동.
- **주의 1**: 이후 단계의 검증은 건너뛴 단계의 결과물에 의존할 수 있습니다.
  챕터 1~4는 순서대로 쌓이는 구조라 건너뛰면 다음 검증을 통과하기 어렵습니다.
  실질적으로 안전한 것은 **GitHub 관련 챕터(5·6)를 건너뛰는 경우**이며,
  이때도 챕터 7(충돌 해결)은 로컬에서만 진행되므로 정상 통과 가능합니다.
- **주의 2**: 학생이 악용하지 못하도록 이 명령의 존재는 학생에게 알리지 마세요.
  완주 판정 시 의심되면 `git log --oneline` 으로 실제 커밋 이력을 확인하면 됩니다
  (skip으로는 커밋 이력이 만들어지지 않습니다).

## 완주 판정

학생 화면에서 `progress` 입력 → 챕터 7개 전부 ✔ 인지 확인.
각 단계는 명령의 실제 실행 결과(저장소 상태)를 검증해야만 넘어가므로,
명령을 실행하지 않고 통과할 수 없습니다.

## 학생이 자주 막히는 지점과 대응

| 상황 | 대응 |
|---|---|
| `시작하기.bat`이 안 열림 / 창이 바로 꺼짐 | Git 미설치가 대부분 (미설치 시 다운로드 페이지가 자동으로 열림). 설치 후 재실행. 그래도 안 되면 수동 실행: 폴더에서 우클릭 → "Open Git Bash here" → `./tutorial.sh` |
| 화면에서 명령을 입력해도 반응이 없음 | Enter를 안 눌렀거나, `명령>` 칸이 아닌 곳(스크롤된 화면)을 보고 있는 경우. `progress` 입력으로 현재 위치 재확인 |
| 튜토리얼 창을 실수로 닫음 | 진행 상황은 `.tutorial-state`에 저장되므로 `시작하기.bat`을 다시 더블클릭하면 이어서 진행됨 |
| 엉뚱한 명령을 입력함 | 튜토리얼이 실행을 막고 "이 단계에서는 이것만 실행할 수 있어요"와 함께 정답 명령을 보여줌 — "화면의 빨간 안내를 소리 내어 읽어 보자"고 유도 |
| 단계가 안 넘어감 | 명령은 맞았지만 결과 검증에 실패한 경우 (예: 파일을 저장 안 하고 Enter). 출력된 진단 문장을 함께 읽기 |
| vim이 열림 | `Esc` → `:q!` → Enter. cheatsheet.md에 탈출법 수록 |
| push 인증 실패 | 브라우저 로그인 창이 다른 창 뒤에 숨는 경우가 많음. 작업표시줄 확인 |
| 원격 관련이 완전히 꼬임 | `git remote remove origin` 후 다시 `remote add`부터 |
| 저장소 자체가 꼬임 | cheatsheet.md "처음부터 다시 시작" — 부끄러운 일이 아님을 강조. `./tutorial.sh reset`은 진행 표시만 초기화하므로, 폴더를 새로 풀고 다시 시작하는 쪽을 안내 |

## 실습 완료 후 학생이 설명할 수 있어야 하는 개념

말로 설명하게 하거나 짝에게 가르치게 해 보세요 (가장 좋은 평가 방법).

1. **repository** — .git 폴더에 이력이 저장되는 공간
2. **working directory / staging area / repository** — 기록의 3단계
3. **commit** — 스냅샷(세이브 포인트). 좋은 메시지의 조건
4. **branch / HEAD** — 평행 우주, 지금 내가 서 있는 곳
5. **merge** — 브랜치 합치기 (충돌이 없으면 자동, 있으면 사람이 결정)
6. **remote / origin** — GitHub에 있는 원격 저장소와 그 별명
7. **push / pull** — 올리기 / 받아오기, 로컬과 원격은 다를 수 있다
8. **Pull Request** — "합쳐 주세요" 요청 + 리뷰 과정
9. **conflict** — 같은 곳을 다르게 고치면 사람이 정해야 한다. 오류가 아니다!

## 챕터·단계 구성 참고 (강사용)

각 챕터의 마이크로 단계 — 학생 질문에 답할 때 참고하세요.
(모든 단계는 "명령 일치 → 실행 → 결과 검증" 순서로 통과됩니다)

| 챕터 | 단계 수 | 구성 (순서대로) |
|---|---|---|
| 1. 준비 & 저장소 | 6 | config 3개(name/email/quotepath) → init → branch -m main → status |
| 2. 첫 커밋 | 5 | edit(이름) → status → add . → status → commit |
| 3. 변경 이력 | 5 | edit(취미) → diff → add → commit → log --oneline |
| 4. 브랜치 & 병합 | 7 | switch -c feature/intro → edit(소개) → add → commit → switch main → merge → branch -d |
| 5. GitHub | 3 | (웹) 저장소 생성 → remote add origin → push -u origin main |
| 6. Pull Request | 8 | switch -c feature/dream → edit(장래희망) → add → commit → push → (웹) PR 생성·Merge → switch main → pull |
| 7. 충돌 | 12 | switch -c theme-red → edit(빨강) → add → commit → switch main → edit(파랑, 같은 내용이면 거부) → add → commit → merge(충돌!) → edit(마커 정리) → add → commit |

특기 사항:
- 챕터 7의 두 번째 edit에서 theme-red와 같은 내용을 쓰면 충돌이 나지 않으므로 튜토리얼이 거부하고 다른 색을 요구합니다.
- 챕터 6의 `git pull`은 PR이 실제로 Merge되었는지(장래 희망이 main에 반영되었는지)까지 검증합니다.
- clone으로 받은 폴더는 `git init` 단계에서 기존 기록을 감지해 학생 확인 후 정리합니다.

`.tutorial-state` 파일은 진행 단계 번호만 저장하며 `.gitignore`에 등록되어 있습니다.
